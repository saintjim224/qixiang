# 《农e保》竞品拆解 —— 对「融天气象」AIC 参赛项目的启示

> 对照对象：工行杯总决赛作品《农e保》（西安交大，遥感+气象+AI 农业保险智能风控平台）
> 对照主体：本项目《融天气象 —— 高原多源时空融合气象灾害预警平台》（AIC·智慧气象）
> 结论口径：只借鉴**结构与打法**，不搬运内容与数据。

---

## 0. 一句话结论

**赛道判断被验证，科学深度我们不输，输在"叙事完整度"和"证据链闭环"。** 农e保恰好把 AIC 六项评分标准逐条答满了；我们把大量精力花在算法正确性上，却在 25 分的"创新性"和 15 分的"应用成效"上留了空位。

## 1. 两个项目的定位对照

| 维度 | 农e保 | 融天气象（我们） |
|---|---|---|
| 行业落点 | 冬小麦主产区 · 农业**保险+信贷** | 青藏高原高寒牧区 · 气象**灾害预警+草畜平衡+绿色金融** |
| 技术主线 | 遥感指数筛选 + DNN 产量模型 + SHAP | SPI 干旱 + GDI 草地退化 + **PU Learning 灾害风险** + NPP 时空预测 |
| 空间尺度 | 陕西渭南 1 市 8 区县，10 m 栅格 | 青藏高原 **4 省区 26 县**，县域尺度 |
| 时间跨度 | 4 年产量对标 | **2001–2025，650 条真实 MODIS 观测** |
| 方法严谨度 | 多元线性回归 + DNN，发表级可复现性一般 | 复现 SCI 论文（*Li et al., 2025*）、WMO SPI 框架、LOYO/LORO 双向协议 ★ |
| 业务闭环 | 保险+信贷双轮，"一地一价"，**已落地验证** | 灾害预警→草畜承载→应急储备→绿色金融，**算法层完整、业务背书待补** |
| 合规 | 公开校名团队名（工行杯允许） | **双盲匿名**（AIC 强制） |

**共同点**：都打「**气象/遥感 × 农业金融**」。这说明该叙事在评审端是被认可的成熟范式——我们的选题方向没有问题，问题在表达。

## 2. 按 AIC 评分表逐项拆解（满分 100）

### 创新性（25 分）· 我们最大的待补项

AIC 规则硬性要求：*"申报时须明确标注**核心创新层级**（数据级/特征级/模型级/系统级/应用级），并与**现有主流方案进行定性对比分析**，阐明相对优势。"*

农e保的答卷方式：
- 开场即立"**团队首创：10 米栅格**，国内外研究最高精度"——用一个可比较的数字锚定创新；
- 收尾用**四维竞品对照表**（产品灵活性 / 风险评估 / 理赔信赖效率 / 数据与风险透明度），自己那行全部"高/精准"，把"相对优势"可视化；
- 再加一句升维话术："从单一工具到系统性解决方案的升维竞争"。

**我们要做的**：
1. **给四大算法各标一个创新层级**。建议：PU Learning 灾害风险评估 → **模型级**（最硬）；SPI 的零降水混合 CDF 边界 → **数据级/特征级**；GDI 论文复现 + 脆弱性系数 → **模型级**；26 县×25 年 LOYO/LORO 协议 → **系统级**。
2. **补一张"主流方案对照表"**。对照对象建议选：传统气象阈值预警法、纯监督学习灾害模型（把未标注当负例）、等权 Min-Max 退化指数、县级气候态基线。每一行给出我们的定性差异。
3. 注意：我们目前的"创新"表述散落在 README 各处，**没有一处集中、可摘录的"创新点清单"**——这是评审最容易失分的地方。

### 需求分析（15 分）· 我们偏弱的一环

农e保做了一条**完整的一手证据链**：座谈采访 51 人 / 发放问卷 360 份 / 实地考察 120 次 + 时间轴（2023.09→2025.07），并在政策分析里画了 2019→2025 的一号文件演进图。

我们目前是**文献驱动 + 数据集驱动**，几乎没有"需求从哪里来"的现场证据（README 里能看到的只有数据源清单）。

**建议**：
- 补一段**政策依据**：青藏高原生态保护、草原生态补奖、乡村振兴、农牧业保险（至少 3 份可引用的中央/部委文件）。
- 补一段**需求来源**：哪怕引用公开的牧民受灾报道、畜牧站公开数据、地方防灾规划文件，也比"无"强。
- ⚠️ 匿名前提下，**不能写"我们访谈了 XX 人"** 这种需要单位背书的表述——改用"公开资料调研 + 数据实证"的合法路径。

### AI 技术应用（20 分）· 我们的强项，但要讲对方法

大纲明确要求分别说清：**① 气象数据的具体作用** + **② AI 技术的选用依据与融合关系**。

农e保把"输入→模型→输出"讲成了一条流水线（气象插值→插入数据→建立模型→结果分析），并给了具体数（105 个指数→筛 6 个→DNN→562 栅格→精度 0.962）。

我们的算法更硬，但 README 的叙述**偏"破题式"**（"破除原版硬伤…"），读起来像是在辩解，而不是在展示。**答辩口径要换成正向叙述**：先说我用了什么、为什么选它、它解决了什么，再谈边界。

### 项目实施（15 分）

农e保给了清晰的**项目历程时间轴**（5 个里程碑）+ 团队分工暗示。

我们需要补一张**开发里程碑时间轴**（匿名版，只写"2025.xx 完成 SPI 重构 / 完成 26 县数据融合 / …"）。不要写真实协作机制细节，写"阶段—产出"即可。

### 应用成效（15 分）· 第二次待补

农e保的成效数字链条极其漂亮，且层层递进：
> 提取误差 **3%** → 难点区 **7~8%** → 面积精度 **93%** → 产量模型精度 **0.962** → 产品精准率 **95%**
> + 保费下降 **25%/35%** + 全国三等奖 + 清华年会 + **陕西省委办公厅采用并获领导批示**

我们目前的指标全是**算法指标**（MAE 0.0117、R²、召回率 0.4286），缺少"**对人的价值**"的量化。

**建议补一组业务价值指标**（都基于我们已有的算法输出，可复现）：
- 26 县覆盖、2001–2025 共 650 条真实观测；
- 14 天积雪窗口 → 预警提前量；
- 应急补饲测算：每县干草/精饲料吨数与采购成本预算（`carrying.py` 已有）；
- 绿色信贷敞口：灾害暴露资产敞口测算 → 差异化授信额度区间。

⚠️ 同时**必须守住我们的诚实底线**：README 反复强调"标签 F1 不能解释为真实灾害识别成绩"——这个边界必须保留，但**放在"效果验证"的限定条件里，而不是开篇**。答辩节奏改为「先立价值 → 再划边界」，评委才听得进去。

### 总结与展望（10 分）

农e保用"三步走战略"图（2025–26 强化验证 → 2027–28 产品服务 → 2029–30 生态构建）。

建议我们也画一张三步走：**① 算法验证（当前）→ ② 平台化/县域推广 → ③ 高原生态智能决策基础设施**。
